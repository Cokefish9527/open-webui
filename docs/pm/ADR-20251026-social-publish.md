# ADR-20251026 — 社媒发布路线定案（云手机 vs Playwright）

## 基本信息
- 决策主题：TikTok 社媒发布的技术路线与合规策略
- 背景/动机：当前“社媒矩阵账号绑定与自动化发布”尚未定案，阻塞 Beta。需在成本、合规、稳定性、维护性之间取舍，并具备回退与灰度能力。
- 决策日期（拟）：2025-10-26
- 责任人/参与人（拟）：PM/后端/前端/外包 n8n 专家/运维/法务顾问（如有）
- 关联里程碑：Beta(2025-11-08)、试点(2025-11-15)、GA(2025-12-15)

## 备选方案
- 方案A｜云手机/设备农场
  - 优点：
    - 与真实终端一致，抗 UI 变更能力强；兼容度高。
    - 可实现多账号并行，隔离性较好。
  - 缺点：
    - 成本较高（设备/云手机时长/运维）；
    - 调度编排复杂，稳定性依赖第三方服务质量；
    - 自动化脚本维护成本与可移植性一般。
  - 风险与合规：
    - 需评估是否触及平台风控（设备指纹、异常登录、IP 画像等）；
    - 需建立风控预案（限速、错峰、人机混合发布）。

- 方案B｜Playwright 自动化浏览器
  - 优点：
    - 资源成本低、易于容器化与 CI/CD 集成；
    - 脚本维护相对便捷，生态成熟。
  - 缺点：
    - 对前端页面变更敏感；
    - 账号风控风险需要专项策略（指纹、代理、Cookie/Session 管理）；
    - 并发/弹性需精心设计（隔离与队列）。
  - 风险与合规：
    - 严格评估 ToS；需准备风控与封禁/限流应对策略。

- 方案C｜半自动（人工确认+系统引导）
  - 作为回退与灰度选项；在方案 A/B 不稳定或合规未决时，确保可控可用。

## 取舍与结论（建议）
- 选定方案：A/B 双线并行验证，优先选 B（Playwright）为主路线；A（云手机）保留为高稳定性与账号隔离的备选路线。
- 边界与不做：暂不做“多平台全量扩展”；仅聚焦 TikTok；不做深度反自动化对抗。
- 迁移/替代计划：若 B 在试点期出现不可接受的封禁/限流，则切换至 A；形成统一“发布适配层”，便于替换实现。

## 验证与回滚计划
- 验证用例/阈值：
  - 1 账号/日 1 条视频稳定发布（连续 3 天），成功率 ≥ 90%；
  - 失败可自动重试 ≤ 2 次；手动回滚/重发可用；
  - 发布耗时 P95 ≤ 5 分钟；
  - 风控事件（验证码/异常登录）发生率 ≤ 5% 且可处理。
- 试点范围与灰度：
  - 先内测再 2–3 家试点；账号/题材/时间错峰；
  - 灰度开关：B→A 或 B→半自动；
- 回滚条件与操作：
  - 近 24 小时内成功率 < 70% 或连续 1 小时失败率 > 50% 即触发回滚至 A/半自动；
  - 脚本：保留队列内任务，切换调度目标；记录回滚工单与原因。
