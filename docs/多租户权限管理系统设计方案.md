# 多租户权限管理系统设计方案

## 1. 概述

本方案旨在将当前单组织管理系统改造为支持多租户的权限管理系统，实现系统管理员->组织管理员->组织成员的三级权限架构，同时保持组织间的数据隔离。

## 2. 设计目标

1. 实现三级权限管理体系：系统管理员 > 组织管理员 > 组织成员
2. 确保组织间数据完全隔离
3. 支持全局账号管理（由外部后台管理系统维护）
4. 最小化对现有系统架构的改动
5. 保持现有权限控制机制的兼容性

## 3. 核心概念

### 3.1 角色定义

1. **系统管理员（System Admin）**
   - 最高权限级别
   - 可以查看和管理所有组织和用户
   - 负责系统级别的配置和维护
   - 可以创建/删除组织和组织管理员

2. **组织管理员（Organization Admin）**
   - 管理特定组织内的所有资源
   - 可以创建/管理组织内的用户和项目
   - 可以查看组织内的所有数据
   - 不能访问其他组织的数据

3. **组织成员（Organization Member）**
   - 普通用户角色
   - 只能访问被授权的组织资源
   - 根据组权限访问特定功能

### 3.2 数据隔离

1. **组织级别隔离**：每个组织的数据完全独立
2. **用户归属**：每个用户必须归属于一个组织
3. **资源归属**：所有业务资源（项目、任务等）必须归属于特定组织

## 5. 权限控制机制

### 5.1 认证与授权流程

1. **系统管理员**：
   - 通过`is_super_admin=True`标识识别
   - 可以访问所有组织的数据
   - 不受组织隔离限制

2. **组织管理员**：
   - 通过`is_org_admin=True`和`organization_id`标识识别
   - 可以访问指定组织的所有数据
   - 不能访问其他组织数据

3. **组织成员**：
   - 通过`organization_id`关联到组织
   - 只能访问所在组织的数据
   - 权限受组权限控制

### 5.2 数据访问控制

在所有数据访问接口中增加组织过滤：

```python
def get_projects_by_user(user):
    query = db.query(Project)
    
    # 系统管理员可以查看所有项目
    if user.is_super_admin:
        return query.all()
    
    # 组织管理员和成员只能查看自己组织的项目
    return query.filter(Project.organization_id == user.organization_id).all()
```

### 5.3 API权限控制

1. **系统级API**（仅系统管理员可访问）：
   - 组织创建/删除
   - 组织管理员指派
   - 全局配置管理

2. **组织级API**（组织管理员和成员可访问）：
   - 项目管理
   - 任务管理
   - 用户管理（仅限本组织）

3. **个人级API**（所有用户可访问）：
   - 个人信息管理
   - 个人任务操作

## 6. 实现方案

### 6.1 用户认证扩展

修改`get_current_user`依赖函数，增加组织信息验证：

```python
def get_current_user(token: str = Depends(oauth2_scheme)):
    # ... 现有认证逻辑 ...
    
    # 验证用户组织信息
    if not user.is_super_admin:
        if not user.organization_id:
            raise HTTPException(status_code=403, detail="用户未分配到组织")
    
    return user
```

### 6.2 权限检查装饰器

创建新的权限检查装饰器：

```python
def require_system_admin(user=Depends(get_current_user)):
    if not user.is_super_admin:
        raise HTTPException(status_code=403, detail="需要系统管理员权限")
    return user

def require_org_admin(user=Depends(get_current_user)):
    if not user.is_super_admin and not user.is_org_admin:
        raise HTTPException(status_code=403, detail="需要组织管理员权限")
    return user

def require_org_access(organization_id: str, user=Depends(get_current_user)):
    if not user.is_super_admin:
        if user.organization_id != organization_id:
            raise HTTPException(status_code=403, detail="无权访问该组织资源")
    return user
```

### 6.3 数据库查询过滤

在所有数据访问层增加组织过滤：

```python
class ProjectsTable:
    def get_projects_by_user(self, user: UserModel):
        with get_db() as db:
            query = db.query(Project)
            
            # 系统管理员可以查看所有项目
            if not user.is_super_admin:
                # 组织管理员和成员只能查看自己组织的项目
                query = query.filter(Project.organization_id == user.organization_id)
            
            return query.all()
```

## 8. 迁移方案

### 8.1 数据迁移

1. 将现有Company表重命名为Organization表（保持数据结构）
2. 为所有现有用户分配到默认组织
3. 指定第一个用户为系统管理员
4. 为现有数据添加组织关联

2. 在用户认证流程中增加组织验证
3. 修改所有数据访问接口增加组织过滤
4. 更新权限检查逻辑

3. **数据加密**：敏感数据加密存储
4. **定期审查**：定期审查权限分配情况
