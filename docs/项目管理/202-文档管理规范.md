## 📝 文档编写规范

### 格式要求
1. 使用Markdown格式编写
2. 文件编码：UTF-8
3. 行尾格式：LF (Unix格式)
4. 缩进：使用4个空格（不要使用Tab）

### 结构规范
```markdown
# 文档标题

## 📋 章节标题

### 小节标题

#### 子小节标题

正文内容...

## 📎 附录（如需要）
```

### 标题规范
- 主标题：`# 文档标题` （使用 📋 图标）
- 章节标题：`## 📋 章节标题`
- 小节标题：`### 小节标题`
- 子小节标题：`#### 子小节标题`

### 内容规范
1. 使用简洁明了的中文表达
2. 重要信息使用列表或表格展示
3. 代码片段使用代码块格式
4. 重要提示使用emoji图标标识：
   - 📋 目录/章节
   - 🎯 目标/要点
   - ✅ 完成/正确
   - ❌ 错误/禁止
   - ⚠️ 警告/注意
   - 💡 提示/建议
   - 🔧 配置/操作
   - 🧪 测试/验证

## 🔄 文档维护流程

### 新增文档
1. 确定文档类型和适当编号
2. 按规范创建文档文件
3. 编写文档内容
4. 更新README.md索引文件
5. 提交Git版本控制

### 更新文档
1. 修改前先pull最新代码
2. 进行必要的内容更新
3. 更新文档版本信息（如适用）
4. 更新README.md索引文件（如适用）
5. 提交Git版本控制

### 归档文档
1. 识别过时或不再适用的文档
2. 将文档移至archive目录
3. 在README.md中更新归档列表
4. 提交Git版本控制

## 📤 版本控制规范

### 提交信息格式
```
docs: 更新文档标题

详细说明文档变更内容
```

### 分支管理
- 主分支：main/master（稳定版本）
- 开发分支：dev/docs（文档开发）
- 功能分支：feature/文档主题

### 发布流程
1. 文档变更在dev/docs分支开发
2. 完成后合并到main分支
3. 打标签记录重要版本
