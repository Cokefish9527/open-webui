# 计费模块前端对接设计文档

## 1. 概述

本文档详细说明了HSAI项目计费模块前端部分的对接设计，描述提供给用户端的计费功能接口，包括用户信息扩展积分数值获取、获取计费明细等功能。

> 文档编号：576  
> 文档版本：v1.0  
> 最后更新：2025-10-15

## 2. 基础URL

所有API接口的基础URL为: `/api/v1/billing`

## 3. 认证

所有API接口都需要有效的认证令牌，通过HTTP头部的`Authorization: Bearer <token>`传递。

## 4. 错误处理

所有API接口都遵循标准的HTTP状态码规范：
- `200`: 请求成功
- `400`: 请求参数错误
- `401`: 未认证
- `403`: 权限不足
- `404`: 资源未找到
- `500`: 服务器内部错误

## 5. 用户端计费功能接口

### 5.1 获取用户积分余额

**GET** `/api/v1/billing/user/credit`

获取当前登录用户的积分余额信息。

#### 请求参数

无

#### 响应示例

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "user_id": "user_123",
    "company_id": "company_456",
    "company_name": "测试公司",
    "credit_balance": 1000.00,
    "last_updated": "2025-10-10T10:00:00Z"
  }
}
```

#### 响应字段说明

| 字段名 | 类型 | 描述 |
|--------|------|------|
| user_id | string | 用户ID |
| company_id | string | 公司ID |
| company_name | string | 公司名称 |
| credit_balance | number | 当前积分余额 |
| last_updated | string | 最后更新时间 |

### 5.2 获取用户积分使用记录列表

**GET** `/api/v1/billing/user/usage-logs`

获取当前登录用户的积分使用记录列表（分页）。

#### 请求参数

| 参数名 | 类型 | 必需 | 描述 |
|--------|------|------|------|
| ps | integer | 否 | 分页大小，默认20，范围1-100 |
| pi | integer | 否 | 分页索引，从1开始，默认1 |
| start_time | string | 否 | 开始时间，格式：YYYY-MM-DD |
| end_time | string | 否 | 结束时间，格式：YYYY-MM-DD |

#### 响应示例

```json
{
  "code": 0,
  "msg": "success",
  "data": [
    {
      "id": 1,
      "user_id": "user_123",
      "session_id": "session_456",
      "service_provider": "openai",
      "model_name": "gpt-4",
      "credits_consumed": 0.3,
      "consumed_at": "2025-10-10T10:00:00Z"
    }
  ],
  "pagination": {
    "total": 1,
    "page": 1,
    "size": 20,
    "total_pages": 1
  }
}
```

#### 响应字段说明

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | integer | 记录ID |
| user_id | string | 用户ID |
| session_id | string | 会话ID |
| service_provider | string | 服务提供商 |
| model_name | string | 模型名称 |
| credits_consumed | number | 消耗的积分数量 |
| consumed_at | string | 消耗时间 |

      "consumed_at": "2025-10-10T10:01:00Z"

#### 响应字段说明

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | integer | 记录ID |
| user_id | string | 用户ID |
| session_id | string | 会话ID |

### 5.4 获取公司积分变动记录

**GET** `/api/v1/billing/user/company-credit-logs`

获取当前用户所属公司的积分变动记录（分页）。

#### 请求参数

| 参数名 | 类型 | 必需 | 描述 |
|--------|------|------|------|
| ps | integer | 否 | 分页大小，默认20，范围1-100 |
| pi | integer | 否 | 分页索引，从1开始，默认1 |
| start_time | string | 否 | 开始时间，格式：YYYY-MM-DD |
| end_time | string | 否 | 结束时间，格式：YYYY-MM-DD |

#### 响应示例

```json
{
  "code": 0,
  "msg": "success",
  "data": [
    {
      "id": "log_001",
      "company_id": "company_001",
      "change_type": "increase",
      "change_amount": 100.00,
      "balance_before": 900.00,
      "balance_after": 1000.00,
      "operator_name": "管理员",
      "operated_at": "2025-10-10T10:00:00Z",
      "remark": "充值"
    }
  ],
  "pagination": {
    "total": 1,
    "page": 1,
    "size": 20,
    "total_pages": 1
  }
}
```

#### 响应字段说明

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | string | 记录ID |
| company_id | string | 公司ID |
| change_type | string | 变动类型（increase: 增加, decrease: 减少） |
| change_amount | number | 变动数量 |
| balance_before | number | 变动前余额 |
| balance_after | number | 变动后余额 |
| operator_name | string | 操作人姓名 |
| operated_at | string | 操作时间 |
| remark | string | 备注信息 |

## 6. 前端页面设计建议

### 6.1 用户积分概览页面

#### 页面功能
- 展示当前用户的积分余额
- 显示最近的积分使用记录
- 提供积分使用记录查询功能

#### 页面元素
1. 积分余额展示区域
   - 当前积分余额
   - 公司名称
   - 最后更新时间
2. 积分使用记录列表
   - 时间
   - 服务提供商
   - 模型名称
   - 消耗积分
3. 查询条件区域
   - 时间范围选择
   - 查询按钮

### 6.2 积分使用详情页面

#### 页面功能
- 根据会话ID展示详细的积分使用情况
- 显示该会话中所有API调用记录
- 显示该会话总消耗积分

#### 页面元素
1. 会话信息展示
   - 会话ID
   - 总消耗积分
2. API调用记录列表
   - 调用时间
   - 服务提供商
   - 模型名称
   - 消耗积分
3. 返回按钮

### 6.3 公司积分变动记录页面

#### 页面功能
- 展示用户所属公司的积分变动记录
- 支持按时间范围查询

#### 页面元素
1. 积分变动记录列表
   - 变动时间
   - 变动类型
   - 变动数量
   - 变动前余额
   - 变动后余额
   - 操作人
   - 备注
2. 查询条件区域
   - 时间范围选择
   - 查询按钮

## 7. 前端交互规范

### 7.1 数据加载
- 页面初始化时自动加载用户积分余额
- 列表数据采用分页加载方式
- 提供加载状态提示

### 7.2 错误处理
- 网络请求失败时显示友好的错误提示
- 服务器返回错误时显示具体错误信息
- 提供重试机制

### 7.3 用户体验
- 页面响应时间应控制在2秒以内
- 提供数据为空时的友好提示
- 支持刷新功能

## 8. 权限控制

### 8.1 访问权限
- 只有已登录用户才能访问计费相关接口
- 用户只能查看自己及所属公司的积分信息

### 8.2 操作权限
- 用户只能查看积分信息，不能进行修改操作
- 积分调整操作仅限管理员在后台进行

## 9. 安全设计

### 9.1 数据安全
- 所有敏感数据传输使用HTTPS协议
- 用户只能访问授权范围内的数据

### 9.2 访问安全
- 所有接口都需要进行身份验证
- 关键接口需要进行频率限制

## 10. 性能优化建议

### 10.1 前端优化
- 对积分使用记录列表进行虚拟滚动优化
- 对时间范围查询添加限制，避免查询过多数据
- 合理使用缓存机制

### 10.2 接口优化
- 对常用查询添加缓存机制
- 对大数据量查询采用分页机制
- 合理设计数据库索引
