# 计费模块前端对接设计文档

## 1. 概述
本文档描述管理端与用户端在计费/积分场景下的前端交互、API 对接与状态管理策略，覆盖公司共享积分、个人日志、充值流程等视图。版本：v1.1（2025-10-23）。

## 2. 角色与入口
- **普通用户**：查看公司可用积分、个人消费记录、发起充值。
- **公司管理员**：除普通能力外，可查看公司维度的积分变动、审批充值。
- **系统管理员**：维护费率、审计日志、导出报表。

入口路径：`管理后台 → 设置 → 积分`、`用户端 → 头像菜单 → 积分`。

## 3. API 对接
### 3.1 获取公司积分余额
- **Endpoint**：`GET /api/v1/billing/user/credit`
- **Headers**：`Authorization: Bearer <token>`
- **响应示例**：
  ```json
  {
    "user_id": "user_123",
    "company_id": "company_456",
    "company_name": "华思创新",
    "credit_balance": 1280.5,
    "last_updated": "2025-10-22T14:30:12Z"
  }
  ```
- **前端缓存策略**：登录后首次加载写入 `creditStore`，其后通过轮询（默认 60s）或触发型刷新（成功下单、完成任务）更新。

### 3.2 用户积分使用记录
- **Endpoint**：`GET /api/v1/billing/user/usage-logs`
- **Query**：`ps`（默认 20，最大 100）、`pi`（从 1 开始）、`start_time`、`end_time`
- **响应**：列表 + `pagination`。前端分页组件透传 `total`、`page`、`size`。

### 3.3 按会话查看详情
- **Endpoint**：`GET /api/v1/billing/user/usage-logs/session/{session_id}`
- 页面在日志列表中点击会话号时弹出侧边抽屉，展示同一会话的所有 API 调用与累计扣费。

### 3.4 公司积分变动记录
- **Endpoint**：`GET /api/v1/credit/logs?pi=&ps=`（普通用户获取个人日志）；管理员端调用 `/api/v1/credit/all_logs` 支持 `query` 模糊检索公司或用户。
- **字段**：`company_id`、`change_type`（increase/decrease）、`change_amount`、`balance_before/after`、`operator_name`、`operated_at`、`remark`。

### 3.5 充值流程
- **创建订单**：`POST /api/v1/credit/tickets`
  - 请求体：`{ "pay_type": "wechat", "amount": 100.0 }`
  - 响应：`{ "id": "202510231030.5b3...", "detail": { ... } }`
- **支付回调**：前端通过 `detail.qr_code_url` 渲染二维码，轮询 `GET /api/v1/credit/tickets/{id}` 同步状态。
- **完成入账**：后端回调成功后写入 `credit` 表并推送通知；前端刷新余额及日志列表。

## 4. 页面设计
### 4.1 积分总览
- 卡片展示公司余额、最近更新时间、累计充值/消耗。
- 支持一键刷新与快捷入口（充值、查看日志、费率说明）。
- 若余额低于阈值（默认 100），突出警示并引导充值。

### 4.2 使用记录列表
- 列表列：日期、会话 ID、服务提供方、模型、消耗积分、备注。
- 支持区间筛选、按模型/服务提供方筛选、导出 CSV。
- 行操作：查看会话详情、复制日志 ID、跳转至对应任务。

### 4.3 公司积分变动
- 管理员视图显示 `change_type`、`operator_name`、`balance_before/after`。
- 支持按操作人、备注关键词搜索；提供近 7/30/90 天快捷筛选。

### 4.4 充值弹窗
- 表单字段：充值金额、支付方式（微信/支付宝/银行卡）、开票需求（可选）。
- 成功后展示订单号与二维码；提供“我已完成付款”按钮触发快速验证。

## 5. 状态管理
- `creditStore`：保存 `credit_balance`、`last_updated`，提供 `refresh()`、`subscribe(callback)`。
- `usageLogStore`：封装分页数据、筛选条件、loading 状态；支持 query key 缓存。
- `ticketStore`：跟踪当前充值订单进度，内建超时与错误提示。

## 6. 交互与异常处理
- 接口失败（40x/50x）统一走 `toast`，并在按钮上展示重试选项。
- 若返回 403 且 `detail` 为 `余额不足`，引导用户跳转充值弹窗。
- 轮询类请求应在页面卸载时清理定时器（使用 `onDestroy`）。

## 7. 与后端协作注意事项
- 所有金额/积分统一保留 2~4 位小数，前端展示时使用 `toFixed(2)`。
- 时间字段统一以 UTC ISO8601（后端返回 `Z` 时区），前端通过 dayjs 格式化。
- 充值回调可能延迟，前端需展示“处理中”状态并提示 1~2 分钟冷却。
- 对于跨公司切换（管理员），应在调用接口前切换 `Authorization` 或附加 `X-Company-ID`（若后端开启）。

## 8. 待办与优化
- 引入 WebSocket/Server-Sent Event，减少轮询压力。
- 公司积分变动页面缺少导出能力，后续补充批量下载。
- 充值票据暂未接入发票流程，需与财务模块对齐。

## 9. 附录
- 颜色规范：主色 `#4A6CF7`，警告色 `#FFB020`，危险色 `#E5484D`。
- 图标：使用内置 Icon 集（Heroicons）；充值按钮采用 `currency-yen` 图标。
- 主要接口封装位于 `src/lib/apis/credit.ts`，组件存放于 `src/routes/(dashboard)/credits/`。
