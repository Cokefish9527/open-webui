## 1. 概述

本方案旨在为 HSAI 系统设计一套高效的素材管理方案，满足以下需求：

1. 为用户提供素材管理入口
2. 支持与 n8n 工作流进行文件交互
3. 使用阿里云 OSS 作为文件存储服务
4. 支持企业信息素材和视频拍摄素材的管理
5. 提高素材上传、检索、下载的效率

## 2. 设计原则

1. **文件名拼接**：场景、手法、空镜等通过文件名拼接的方式体现，便于其他服务通过预期的命名调用文件
2. **属性存储**：文件属性保存在文件数据表中，通过获取指定文件属性的接口调用得到
3. **分类管理**：对于用在文件名拼接上的分类，使用英文+分类表维护的方式管理，保证文件名可读性的同时，可以在数据库维护分类，提供一个后续查阅的途径，但是分类名需要控制在10个字符以内，避免文件名过长
4. **字符编码**：作为文件名拼接的元素，必须是英文字符，不能是中文字符，避免编码错误
5. **压缩包支持**：支持压缩包上传解析，通过解析压缩包的目录结构，将文件按照规则执行重命名、保存数据库等操作

## 3. 数据模型设计

### 3.1 素材分类表 (HSAIMaterialCategory)

用于管理场景、手法、属性分类：

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | String | 分类唯一标识符 |
| name | String | 分类名称（英文，10字符以内） |
| display_name | String | 显示名称（中文） |
| category_type | String | 分类类型（scene, technique, property） |
| description | Text | 分类描述 |
| is_active | Boolean | 是否启用 |
| created_at | BigInteger | 创建时间 |
| updated_at | BigInteger | 更新时间 |

### 3.2 素材表 (HSAIMaterial)

在原有素材表基础上增加了分类相关字段：

| 字段名 | 类型 | 描述 |
|--------|------|------|
| scene_code | String | 场景代码 |
| technique_code | String | 手法代码 |
| properties_code | String | 属性代码（多个属性用下划线分隔） |
| duration | Integer | 视频时长（秒） |
| resolution | String | 视频分辨率 |
| oss_bucket | String | OSS Bucket |
| oss_key | String | OSS对象键 |
| is_deleted | Boolean | 删除标志位（true表示已删除） |
| original_directory | String | 原始目录（软删除时保存文件原始所在目录） |
| deleted_at | BigInteger | 删除时间（软删除时间） |
| deleted_by | String | 删除人ID（软删除操作人） |

## 4. API 接口设计

### 4.1 分类管理接口

#### 获取素材分类列表
```
GET /hsai/materials/categories
```

参数：
- category_type (可选): 分类类型过滤（scene, technique, property）

#### 创建素材分类
```
POST /hsai/materials/categories
```

参数：
- name: 分类名称（英文，10字符以内）
- display_name: 显示名称（中文）
- category_type: 分类类型（scene, technique, property）
- description: 分类描述
- is_active: 是否启用

#### 更新素材分类
```
PUT /hsai/materials/categories/{category_id}
```

参数：
- name: 分类名称（英文，10字符以内）
- display_name: 显示名称（中文）
- category_type: 分类类型（scene, technique, property）
- description: 分类描述
- is_active: 是否启用

#### 删除素材分类
```
DELETE /hsai/materials/categories/{category_id}
```

### 4.2 素材管理接口

#### 上传素材
```
POST /hsai/materials/upload
```

参数：
- file: 要上传的文件（支持单个文件或ZIP压缩包）
- name (可选): 素材名称
- description (可选): 素材描述
- folder_id (可选): 目标文件夹ID
- tags (可选): 标签列表（JSON格式）
- auto_analyze: 是否自动进行AI分析
- scene_code (可选): 场景代码
- technique_code (可选): 手法代码
- properties_code (可选): 属性代码（JSON格式）

#### 获取素材属性
```
GET /hsai/materials/{material_id}/properties
```

### 4.3 回收站管理接口

#### 移入回收站（软删除）
```
POST /hsai/materials/{material_id}/move-to-recovery
```

参数：
- material_id: 素材唯一标识符
- operator_id: 操作人ID
- reason (可选): 删除原因

说明：将指定素材从原目录移动到回收站目录，在数据库中更新删除标志位和原目录信息，记录操作日志

#### 还原文件
```
POST /hsai/materials/recovery/{material_id}/restore
```

参数：
- material_id: 素材唯一标识符
- target_directory: 目标目录（materials/drafts/published）
- operator_id: 操作人ID

说明：将回收站中的文件还原到指定目录，更新数据库记录，记录操作日志

#### 永久删除文件
```
DELETE /hsai/materials/{material_id}/permanent-delete
```

参数：
- material_id: 素材唯一标识符
- operator_id: 操作人ID
- reason (可选): 删除原因

说明：根据素材ID在素材表中找到对应的记录，通过素材文件的位置信息确定需要删除的OSS文件（企业目录或回收站目录中的文件），彻底删除OSS文件和数据库记录，记录操作日志。此接口统一处理所有永久删除操作，客户端无需关心文件具体位置。

#### 获取回收站文件列表
```
GET /hsai/materials/recovery/list
```

参数：
- enterprise_id: 企业ID
- page (可选): 页码，默认1
- size (可选): 每页数量，默认20
- sort_by (可选): 排序字段（delete_time/name/size），默认delete_time
- order (可选): 排序方式（asc/desc），默认desc

说明：获取指定企业回收站中的文件列表

#### 批量操作回收站文件
```
POST /hsai/materials/recovery/batch-operation
```

参数：
- operation: 操作类型（restore/delete）
- material_ids: 素材ID列表（JSON数组）
- target_directory (可选): 目标目录（restore操作时必需）
- operator_id: 操作人ID

说明：对回收站中的多个文件进行批量还原或删除操作

### 4.4 文件操作日志接口

#### 记录文件操作日志
```
POST /hsai/materials/logs
```

参数：
- material_id: 素材唯一标识符
- operation_type: 操作类型（upload/delete/restore/move/modify）
- source_path: 源文件路径
- target_path: 目标文件路径（可选）
- operator_id: 操作人ID
- operation_time: 操作时间
- details (可选): 操作详情（JSON格式）

说明：记录文件操作日志，由系统自动调用

#### 查询文件操作日志
```
GET /hsai/materials/logs
```

参数：
- material_id (可选): 素材唯一标识符
- enterprise_id (可选): 企业ID
- operation_type (可选): 操作类型
- operator_id (可选): 操作人ID
- start_time (可选): 查询起始时间
- end_time (可选): 查询结束时间
- page (可选): 页码，默认1
- size (可选): 每页数量，默认20

说明：查询文件操作日志

#### 获取文件操作历史
```
GET /hsai/materials/{material_id}/history
```

参数：
- material_id: 素材唯一标识符
- page (可选): 页码，默认1
- size (可选): 每页数量，默认20

说明：获取指定文件的所有操作历史记录

## 5. 文件命名规范

### 5.1 命名格式

文件名采用以下格式：
```
{素材名称}_{场景代码}_{手法代码}_{属性代码}_{文件哈希}.{扩展名}
```

示例：
```
企业介绍_frontdoor_overhead_silent_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6.mp4
```

### 5.2 分类代码规范

1. **场景代码**：描述拍摄场景，如 `frontdoor`（正门口）、`office`（办公室）等
2. **手法代码**：描述拍摄手法，如 `overhead`（俯拍）、`tracking`（跟拍）等
3. **属性代码**：描述素材属性，如 `silent`（无声）、`voiced`（有声）等

所有分类代码均使用英文，长度控制在10个字符以内，非英文字符将被自动过滤。

## 6. 压缩包处理逻辑

系统支持ZIP压缩包上传，能够自动解析压缩包内的目录结构并按规则处理文件：

1. 解压上传的ZIP文件
2. 遍历压缩包内的文件结构
3. 根据目录层级确定分类代码：
   - 第一层目录作为场景代码
   - 第二层目录作为手法代码
4. 生成符合规范的文件名
5. 逐个上传文件到OSS
6. 在数据库中创建对应的素材记录

示例目录结构：
```
materials.zip
├── frontdoor/
│   ├── overhead/
│   │   ├── video1.mp4
│   │   └── image1.jpg
│   └── tracking/
│       └── video2.mp4
└── office/
    └── closeup/
        └── video3.mp4
```

处理后的文件名：
- `video1_frontdoor_overhead_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6.mp4`
- `image1_frontdoor_overhead_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6.jpg`
- `video2_frontdoor_tracking_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6.mp4`
- `video3_office_closeup_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6.mp4`

## 7. 文件解析逻辑

系统提供文件名解析功能，可以从文件名中提取分类信息：

1. 提取文件哈希值（文件名最后32位）
2. 移除哈希值获取基础文件名
3. 按下划线分割文件名组件
4. 第一个组件为素材名称
5. 后续组件依次为场景代码、手法代码、属性代码

## 8. 与 n8n 工作流集成

视频合成服务可以直接使用这种结构化的文件名，通过拼接预期的命名来调用文件：

1. 根据工作流脚本需求确定场景、手法、属性
2. 构造预期文件名
3. 通过 OSS API 获取文件
4. 进行视频合成处理

## 9. OSS目录规划

为了更好地组织和管理素材文件，系统在阿里云 OSS 中采用层次化的目录结构进行存储。OSS 目录规划遵循以下原则：

1. **企业隔离**：不同企业的素材存储在不同的顶层目录中，确保数据隔离
2. **分类存储**：按照素材类型和用途进行分类存储
3. **回收站机制**：提供文件回收站功能，防止误删
4. **生命周期管理**：自动清理过期文件，节省存储空间

### 9.1 目录结构设计

OSS 目录采用以下层次化结构：

```
{bucket_name}/
├── enterprises/
│   ├── {enterprise_id}/
│   │   ├── materials/           # 素材文件
│   │   ├── drafts/              # 草稿文件
│   │   └── published/           # 已发布文件
│   └── shared/                  # 共享素材（跨企业）
│       ├── public/              # 公共素材库
│       └── licensed/            # 授权素材库
└── recovery/                    # 回收站
    └── {enterprise_id}/         # 按企业分组的回收文件
```

### 9.2 目录命名规范

1. **企业目录**：使用企业唯一标识符（enterprise_id）作为目录名
2. **素材目录**：`materials` 用于存储原始素材和处理后的素材
3. **草稿目录**：`drafts` 用于存储未完成的文件
4. **发布目录**：`published` 用于存储已完成并发布的文件
5. **共享目录**：`shared` 用于存储跨企业共享的素材
6. **回收目录**：`recovery` 用于临时存储删除的文件

### 9.3 存储策略

1. **热存储**：`materials/latest` 和 `published` 目录中的文件采用热存储，确保快速访问
2. **冷存储**：超过30天的历史文件自动转为冷存储，降低成本
3. **归档存储**：超过1年的文件转为归档存储，需要时可恢复
4. **生命周期管理**：
   - 回收站中的文件超过30天自动清除
   - 设置自动清理策略，删除超过2年的历史文件

### 9.4 回收站机制

系统提供回收站功能，防止用户误删重要文件：

1. **软删除**：调用OSS删除指令时，将文件移动到回收站而非直接删除
2. **用户操作**：
   - 用户可选择永久删除回收站中的文件
   - 用户可选择还原文件（移动回原目录）
3. **自动清理**：回收站中的文件在30天后自动清除
4. **阿里云OSS集成**：充分利用阿里云OSS的生命周期管理功能，减少开发工作量

### 9.5 访问控制

1. **企业级隔离**：每个企业只能访问自己目录下的文件
2. **角色权限**：不同角色具有不同的目录访问权限
   - 管理员：完全访问权限
   - 编辑者：读写权限
   - 查看者：只读权限
3. **临时授权**：通过签名URL提供临时访问权限

## 10. 性能优化

1. **OSS 存储**：使用阿里云 OSS 作为文件存储服务，提供高可用性和可扩展性
2. **元数据索引**：在数据库中存储文件元数据，支持快速检索
3. **分类表维护**：通过分类表维护分类信息，便于管理和查询
4. **文件名规范**：通过规范化的文件名，其他服务可以直接通过预期的命名调用文件
5. **批量处理**：支持压缩包批量上传，提高上传效率

## 11. 安全考虑

1. **访问控制**：素材访问需经过用户身份验证
2. **文件类型验证**：上传时验证文件类型和大小
3. **数据加密**：敏感数据在传输和存储时进行加密
4. **日志记录**：记录素材操作日志，便于审计
