# WebSocket 调试页前端优化计划（免后端改动）

> 依据《WebSocket 调试页面开发手册》（2025-10-27 版）梳理，仅涉及 `websocket-test.html` 与 `static/ws-tester.js` 的前端调试体验增强，兼顾服务端既有接口。

## 1. 目标与范围
- **页面体验**：缓解任务标签页“布局失衡、内容溢出”问题，提供项目摘要、任务列表与事件日志的清晰分区。
- **交互一致性**：补齐手册中提到的刷新概览、模板创建、状态更新等按钮状态机，确保文档与页面一致。
- **可观察性**：强化任务事件流显示（类型、时间、会话、进度），新增错误提示与操作反馈。
- **可维护性**：对现有逻辑做最小重构，避免接口、数据库改动；保持与后端 2025-10-27 文档描述兼容。

## 2. 交付物
1. 更新后的 `websocket-test.html` 布局（新增摘要区域、任务卡片分栏、滚动容器）。
2. `static/ws-tester.js` 交互增强：
   - 合理的按钮启用/禁用策略与加载指示。
   - 补充错误提示（请求异常、JSON 校验、任务未选择等）。
   - 任务事件流格式化输出（状态徽章、进度百分比、会话 ID）。
   - 修复模板字符串残留问题，保证脚本可直接加载。
3. 针对改动的最小单元测试或手动验证脚本说明（可通过浏览器调试步骤体现）。
4. 文档同步：`docs/410_websocket_test_page_manual.md` 与 `PROJECTWIKI.md` 对应段落的增量更新。

- **D0 上午**：完成 F1-F2，提交前端初稿。

- **D1 上午**：补齐 F5 文档同步，交叉复核与代码 Review 调整。
- **D1 下午**：准备合入/提交（含自检清单、WIKI 链接）。

## 5. 风险与缓解
- **旧接口不兼容**：仅依赖 `/api/v1/hsai/tasks`、`/projects`、`/companies`；若接口字段缺失，提供默认回退并记录在事件日志中。
- **布局回归**：新增样式可能影响移动端，需要通过浏览器设备模拟快速验证；如样式冲突，可增加局部命名空间（`.tasks-grid`）。
- **脚本体量较大**：重构需谨慎保持函数颗粒度；建议分段提交并自测 `npm run lint` / 浏览器加载。

## 6. 验证策略
- 浏览器手动测试：登录、刷新任务概览、创建主线、切换事件过滤、触发错误请求。
- 事件日志自查：确认状态、进度徽章显示正确，错误消息可读。
- 文档核对：手册与实际 UI 要素（按钮名称、事件类型）一致。
